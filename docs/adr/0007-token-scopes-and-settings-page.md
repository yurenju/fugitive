# 存取權杖分讀取與寫入；刪除儲存庫與撤銷別的工具的權杖只能在設定頁做

部分取代 [ADR 0004](0004-oauth-tokens-for-every-client.md)：定下權限範圍與期限；主機的畫面從一個變成兩個。

存取權杖分成讀取 (`read`) 與寫入 (`write`) 兩種權限範圍，`write` 包含 `read`，建立儲存庫也算在 `write` 裡。但**刪除儲存庫和撤銷別的工具的存取權杖，不屬於任何權限範圍**：不管哪一組存取權杖都做不到，只能在瀏覽器的設定頁輸入驗證碼之後做。理由是這兩件事做了回不去，而拿著權杖的通常是 agent。權杖外洩、或 agent 判斷錯的時候，最多只能改寫內容，不能把整個儲存庫刪掉，也不能把使用者其他工具的權杖都撤掉。所以主機沒有「刪除儲存庫」的 API，這是故意的，不是漏做。

## 考慮過的選項

- **另外開一個 `account` 權限範圍給這些動作**：可以用 API 做，但沒有一個工具適合一直拿著它，最後還是要回到瀏覽器。
- **全部算在 `write` 裡**：最簡單，但給 Claude chat 的那組權杖一旦外洩，就能刪掉所有儲存庫。
- **限定某些儲存庫的權限範圍**（ADR 0004 舉的例子）：先不做。目前所有儲存庫都是私有、只有擁有者在用；之後需要時再加一種新的權限範圍，已經發出去的權杖意義不變。讀取與寫入就不一樣，之後才分的話，已經發出去的權杖到底算哪一種會說不清楚，所以現在就分。

## 後果

- 工具沒要求任何權限範圍時給 `write`（很多 MCP 用戶端不會要求）。授權頁上只有一個「只允許讀取」的勾選，預設不勾。
- 主機從「只有授權頁一個畫面」變成兩個畫面：授權頁與設定頁。設定頁上能看到自己發出去的權杖（哪個工具、權限範圍、建立時間、最後使用時間）、撤銷權杖、刪除儲存庫。
- 工具仍然可以用標準的撤銷端點（RFC 7009）撤銷**自己那一組**權杖，例如 helper 登出；這不會傷到別的工具。
- **refresh token 的滑動期限是我們自己做的。** [ADR 0004](0004-oauth-tokens-for-every-client.md) 要的是「閒置超過一段時間才失效，用過一次就重算」，但 `workers-oauth-provider` 0.10.3 的 `refreshTokenTTL` 是從授權那一刻起算的固定期限，換新時不會延長。所以授權本身不設期限；核准授權時與每次換新時（套件換新時會呼叫 `tokenExchangeCallback`），把當下的時間存進授權的 `props`，距離上次超過 90 天就撤銷這個授權、要求重新登入。這個時間也拿來顯示設定頁上的「最後使用時間」，因為套件沒有這一欄。代價是一個沒人再用、也沒人撤銷的授權，紀錄會一直留在 KV 裡（它已經換不到新權杖，只是佔空間）。
- 存取權杖 1 小時有效，所有工具都一樣（套件的預設值）。
- 關掉套件的 `revokeExistingGrants`。`git` helper 對主機來說是同一個工具，開著的話，在第二台電腦授權就會把第一台的授權撤銷。
- 套件只把權限範圍記在權杖上，**不會替我們擋請求**。push、移動分支、建立儲存庫、之後的檔案 API 與 MCP 工具，每個入口都要自己檢查權杖上有沒有需要的權限範圍。
